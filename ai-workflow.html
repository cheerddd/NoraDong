02 · Use Cases

真实使用场景

以下均为实际工作中沉淀的 AI 协作案例，不是想象中的工作流，是每天都在用的产出物。

📄 PRD 生成
分阶段 PRD 生成工作流
将客户需求描述 + Figma 原型链接 + 历史需求文档喂给 Claude，分七个阶段自动完成：需求分析 → 原型图解析 → 历史需求匹配 → 功能设计 → 规则匹配 → 文档生成 → 逻辑检查。每阶段暂停确认，避免黑盒输出。输出包含 Mermaid 流程图、用户故事、验收标准、异常场景。
✅ 单份 PRD 生成时间从半天压缩至 1-2 小时
🔀 增量合并
增量需求文档智能合并
客户迭代需求往往是在原有全量文档基础上的局部改动。通过专项 Prompt 让 Claude 分析增量文档涉及的目录，自动合并进全量文档——区分"老功能改造"/"老功能新增"/"全新功能"三种合并策略，合并后语言自然融入原文，不出现"新增/改动"等破坏文档连贯性的描述。
✅ 全量文档维护效率提升，版本一致性显著改善
🌐 网站开发
用 Claude 独立交付三个网站
Portfolio 个人网站、AddSecure 项目展示页、Local Player 媒体播放页，均由 Claude 完成从设计到代码的全链路输出。通过 PRD 描述 → Claude 生成 HTML/CSS/JS → 反复调试优化的协作模式，无需专业前端背景也能交付具有设计质感的产品。对比测试结论：Claude 在页面美观度和设计审美上优于 Cursor、Trae 等工具。
✅ 零前端背景，独立交付 3 个完整网站
✉️ 客户沟通
AI 润色英文客户邮件
与 AddSecure 欧洲团队的日常沟通以英文为主。在中文起草邮件核心意图后，使用 Claude 将其转化为更 Native 的英文表达——不只是翻译，而是语气、措辞、礼貌程度的全面校准，确保在跨文化商业沟通中给客户留下专业印象。也用于整理全日语资料（Clarion 日本客户）时的结构化提炼。
✅ 跨文化沟通效率和客户体验双提升
03 · Prompts

沉淀复用的 Prompt 模板

好的 Prompt 是可以反复使用的资产。以下是工作中沉淀下来的核心提示词框架，每一个都经过多轮迭代验证。

Prompt 01 · PRD 生成 Claude · 需求文档
你是一个高级产品经理助手，请严格按照以下要求协助我完成需求文档的分阶段输出：

【目标】
1. 请先让我提供：需求描述 + Figma 原型图链接
2. 分阶段输出需求文档：
　　① 分析需求描述 → ② 分析原型图 → ③ 分析历史需求
　　→ ④ 结合分析结果 → ⑤ 匹配规则 → ⑥ 生成文档 → ⑦ 检查逻辑
3. 每个阶段完成后暂停，询问"是否需要修改/补充"
　　回复"继续"才进入下一阶段

【输出要求】
• 包含 Mermaid 流程图、用户故事、验收标准
• 覆盖异常场景和影响范围
• 格式：Markdown 文件
Prompt 02 · 增量需求合并 Claude · 文档管理
你是一个高级产品经理助手，把「增量需求文档」按规则分阶段合并进「全量需求文档」。

【三个阶段】
① 分析增量文档：确定涉及哪些目录，判断增量类型
　　（全新功能 / 老功能改造 / 老功能新增功能）
② 合并增量文档：先备份，再合并
　　合并后语言自然融入，不出现"新增/增加/改动"等描述
③ 逻辑检查：检查流程图，确认合并完成后再删备份

【核心规则】
• 禁止跳步、禁止无备份合并
• Figma 链接信息面与原文一致，不改写
• 用户确认"继续"才进入下一阶段
Prompt 03 · 英文邮件润色 Claude · 客户沟通
你是一位资深的国际商务沟通专家，帮我优化以下英文邮件：

【背景】
• 收件方：[客户名称]，[职位]，来自[国家/地区]
• 沟通目的：[确认需求 / 跟进进度 / 解释方案]
• 语气要求：专业、友好、简洁

【优化要求】
• 使表达更 Native，避免中式英语
• 保留核心意思，不过度简化技术细节
• 适当使用 please / would appreciate 等礼貌表达
• 结尾加清晰的 call to action

原始邮件：[粘贴邮件内容]
